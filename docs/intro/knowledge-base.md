# 知识库与知识图谱

Yuxi 提供了强大的知识管理能力，将知识以向量和图谱两种形式存储，既支持传统的语义检索，又能构建结构化的知识关系网络。

## 为什么需要知识库

在大模型应用场景中，仅依靠模型的内部知识往往不够准确和全面。通过构建知识库，我们可以：

- **注入私有知识**：让模型能够回答基于私有文档的问题
- **降低幻觉**：回答内容可追溯到原始文档
- **知识复用**：一次上传，多轮对话中重复使用

## 知识库存储

系统当前使用 LightRAG 作为知识库实现，并通过 PostgreSQL/pgvector 存放向量数据。文档入库后既可以进行语义检索，也可以抽取实体与关系，构建面向个人资料的知识图谱。

## 创建知识库

访问 Web 界面的「知识库管理」页面，点击「新建知识库」：

1. 填写知识库名称和描述
2. 选择嵌入模型、分块策略和语言模型
3. 保存

::: tip 提示
知识库的名称和描述会被智能体用来判断何时应该使用这个知识库进行检索，所以请尽量详细地描述。
:::

## 内容处理流程

内容从导入到可检索，通常经历三个阶段。来源可以是本地文件、ZIP 压缩包，也可以是网页 URL。

### 1. 上传阶段

将本地文件上传到服务器，或通过 URL 创建网页读取会话。本地文件保持原始格式存储；网页会先保存抓取会话，等待用户选择页面和清洗结果。

### 2. 解析阶段

系统将内容转换为 Markdown 格式：
- 提取文本内容
- 图片上传到 MinIO，并在 Markdown 中用 URL 引用
- 表格、公式等保持结构化
- 网页内容会先去除导航、页脚、脚本、广告等噪声，并生成可预览和可编辑的 Markdown

### 3. 入库阶段

系统对 Markdown 内容进行分块，向量写入 PostgreSQL/pgvector。根据入库模式不同，系统可以只写入 chunks 和向量，也可以通过 LightRAG 提取实体和关系，构建知识图谱到 Neo4j。

在前端界面中，默认会自动完成前两个阶段。如果需要自动入库，勾选「上传后自动入库」选项；否则需要手动点击入库按钮。

## 网页读取与清洗

在知识库文件上传窗口中切换到 URL 导入后，可以创建网页读取会话。系统会读取初始页面，发现同域 HTML 子页面，并按照与初始页面的 embedding 相似度排序，方便优先选择相关页面。

网页不会直接把原始 HTML 写入知识库。推荐流程是：

1. 输入 URL 和最大深度，创建读取会话。
2. 在页面树中展开和勾选需要入库的页面。
3. 打开「预览并清洗」，查看原网页预览和页面树。
4. 生成清洗结果后，逐页检查 Markdown。
5. 对残留广告、导航、版权说明等内容进行编辑或删除。
6. 确认后选择快速入库、标准入库或图谱入库。

只有清洗结果列表中保留的页面会进入本次入库任务。清洗产物会保存到 MinIO，并作为预处理后的 Markdown 复用现有文档处理任务。

## 入库模式

Yuxi 提供三种入库模式：

- **快速入库**：只生成 chunks 和向量索引，适合先快速验证 RAG 检索效果。
- **标准入库**：保留常规 RAG 入库流程，并可限制本次新增图谱节点和关系数量，适合多数正式资料。
- **图谱入库**：更偏向完整构建实体关系，适合明确需要图谱浏览、图谱检索和关系分析的资料。

标准入库和图谱入库可以设置最多节点和最多关系。限制越小，入库越快，图谱越精简；限制越大，图谱更丰富，但耗时也会增加。

## 知识图谱

系统支持两种图谱相关能力，理解它们的区别很重要：

### LightRAG 图谱

针对单个知识库由 LightRAG 自动抽取实体和关系。特点：
- 自动从文档中提取
- 附属于特定知识库
- 用于该知识库内的图增强检索
- 通过知识库 ID 作为 Label 区分，与全局图谱隔离

### 全局知识图谱

通过普通资料抽取并经过人工校对后写入的系统级图谱数据。特点：
- 从文件内容中自动识别候选关系
- 写入前支持人工校对
- 系统级知识库
- 提供图查询和可视化能力
- 作为工具供智能体调用

两者共享同一个 Neo4j 实例，但数据完全隔离，互不影响。

### 全局图谱构建

当前全局知识图谱面向用户的主要入口是普通文件上传和自动关系识别。系统会从资料中抽取候选实体关系，在写入 Neo4j 前提供关系增删改校对流程。校对完成后，可以在图谱可视化页面查看和查询。

单个知识库内的 LightRAG 图谱仍由知识库文档入库自动构建；全局图谱与 LightRAG 知识库图谱共享 Neo4j 实例，但通过标签和数据边界隔离。

### Neo4j 配置

Neo4j 连接信息可以在 `.env` 中配置：

- 默认账户：`neo4j`
- 默认密码：`0123456789`
- 管理界面：http://localhost:7474
- 连接地址：bolt://localhost:7687

::: warning 注意事项
确保每个节点都有 `Entity` 标签和 `name` 属性，每个关系都有 `RELATION` 类型和 `type` 属性，否则会影响图的检索与构建功能。
:::

## 常见问题

**Q：只有节点没有边怎么办？**

A：这通常是因为模型调用量受限。请尝试：
- 更换 TPM（每分钟令牌数）更大的模型
- 更换模型服务商

**Q：构建图谱时出现超时错误？**

A：可以配置增加超时时间：
```env
EMBEDDING_TIMEOUT=60
LLM_TIMEOUT=180
```

**Q：LightRAG 和全局图谱有什么区别？**

A：简单理解：
- LightRAG 图谱 = 自动从知识库文档中提取，附属于知识库
- 全局图谱 = 手动导入，系统级图谱查询

## API 使用

如果需要通过程序批量处理文件，可以使用以下接口：

```bash
# 1. 上传文件
POST /api/knowledge/files/upload?db_id=<知识库ID>
# 返回 file_path 和 content_hash

# 2. 解析并入库
POST /api/knowledge/databases/{db_id}/documents
# 返回 status=queued 和 task_id
```

网页读取相关接口位于 `/api/knowledge/web-reader/sessions` 下，覆盖创建会话、展开页面、更新选择、预览、清洗、编辑清洗结果和提交入库。前端已经封装在 `web/src/apis/knowledge_api.js` 中，优先通过知识库上传窗口使用。

系统会自动去重：基于内容哈希判断是否已存在相同文件。
