# 文档处理、网页读取与 OCR

Yuxi 支持多种文档格式和网页内容的入库处理。无论是本地文件、压缩包、PDF、图片，还是从 URL 读取的网页，系统都会先把原始内容转换成可解析、可分块、可检索的文本，再根据你选择的入库模式写入知识库。

## 入库流程概览

添加内容到知识库时，通常会经过下面几个阶段：

1. **选择来源**：上传本地文件、上传文件夹/压缩包，或输入 URL 读取网页。
2. **解析或清洗**：普通文件会进入解析流程；网页会先发现页面，再生成可查看和编辑的清洗结果。
3. **选择入库模式**：根据速度和图谱需求选择快速入库、标准入库或图谱入库。
4. **提交处理任务**：系统把内容写入知识库，并在任务中心展示处理进度。

如果你只是想尽快让文档可被 RAG 检索，可以选择快速入库。如果你希望后续使用知识图谱能力，应选择标准入库或图谱入库，并设置合适的节点和关系数量限制。

## 支持的文件类型

### 常规文档

| 类型 | 格式 | 说明 |
|------|------|------|
| 文本 | .txt, .md, .html | 直接提取内容 |
| Word | .docx | 保留格式和结构 |
| PDF | .pdf | 支持文本和图片 PDF |
| 表格 | .csv, .xls, .xlsx | 识别表格结构 |
| JSON | .json | 结构化数据 |

### 图片文件

对于图片文件，需要启用 OCR 才能提取文字：
- .jpg, .jpeg, .png, .bmp, .tiff, .tif, .gif, .webp

### 压缩包

支持上传 ZIP 压缩包，系统会：
- 自动提取并处理其中的 Markdown 文件
- 处理图片并上传到对象存储
- 智能识别 `full.md` 或第一个 `.md` 文件

### 网页内容

支持通过 URL 读取网页内容。网页读取不是直接把原网页 HTML 入库，而是经过“发现页面、人工选择、清洗确认、再入库”的流程：

1. 输入一个或多个 URL，并设置最大深度。
2. 系统读取初始网页，发现同域 HTML 子页面。
3. 子页面按 embedding 相似度排序，便于优先选择更相关的页面。
4. 在“预览并清洗”中查看网页原始预览和页面树。
5. 勾选需要入库的页面，生成清洗结果。
6. 查看清洗后的 Markdown，必要时手动编辑或删除某页。
7. 确认后选择入库模式并添加到知识库。

网页清洗会尽量移除导航、页眉页脚、脚本、样式、弹窗和广告等噪声，并保留标题、正文段落、列表、代码块等内容。由于不同网站结构差异很大，自动清洗无法保证每次都完全干净，因此系统提供了清洗结果预览和编辑入口。

### 网页读取会话接口

网页读取由后端会话接口管理，前端知识库上传窗口已经封装完整流程：

| 能力 | 接口 |
|------|------|
| 创建读取会话 | `POST /api/knowledge/web-reader/sessions` |
| 展开已发现页面 | `POST /api/knowledge/web-reader/sessions/{session_id}/expand` |
| 更新入库选择 | `PUT /api/knowledge/web-reader/sessions/{session_id}/selection` |
| 预览页面 HTML | `GET /api/knowledge/web-reader/sessions/{session_id}/preview` |
| 生成清洗结果 | `POST /api/knowledge/web-reader/sessions/{session_id}/clean` |
| 读取清洗 Markdown | `GET /api/knowledge/web-reader/sessions/{session_id}/cleaned-page` |
| 保存清洗 Markdown | `PUT /api/knowledge/web-reader/sessions/{session_id}/cleaned-page` |
| 删除清洗页面 | `DELETE /api/knowledge/web-reader/sessions/{session_id}/cleaned-page` |
| 提交入库任务 | `POST /api/knowledge/web-reader/sessions/{session_id}/commit` |

创建会话需要提供 `url`、`db_id` 和可选 `max_depth`。初始页面默认参与清洗和入库；子页面需要在选择列表中勾选后才会参与后续清洗。

### 清洗结果如何处理

生成清洗结果后，你可以在右侧“清洗结果”中逐页查看 Markdown：

- **预览**：查看清洗后的最终文本形态。
- **编辑**：手动删除残留广告、导航、版权说明或无关段落。
- **保存**：保存修改后的 Markdown，后续入库会使用保存后的版本。
- **删除**：从本次入库中移除整页内容。

只有清洗结果列表中保留的页面会被提交入库。如果你删除了某一页，它不会参与本次知识库处理。

### 网页图片和样式

网页预览使用系统抓取到的 HTML 在安全 iframe 中展示。部分网站的图片、样式、字体或脚本可能因为相对路径、跨域限制、登录权限或网站防护策略无法完整显示。这通常不影响文本清洗和 RAG 入库，但如果页面主要内容依赖图片，建议后续改用文件上传或单独处理图片 OCR。

### 网页读取限制

- 当前只发现同域 HTML 页面，不会跨站点抓取。
- `max_depth` 控制页面树展开深度，设置过大可能导致抓取耗时明显增加。
- 页面排序依赖知识库配置的 embedding 模型；知识库缺少 embedding 配置时无法创建网页读取会话。
- 需要登录权限，且会话只允许创建者继续预览、清洗和提交。
- 登录墙、反爬策略、强脚本渲染页面可能无法完整读取正文。

## 入库模式选择

### 快速入库

快速入库只生成文本 chunks 和向量索引，不生成知识图谱。它适合下面的场景：

- 想尽快让内容可被检索和问答使用。
- 文档数量较多，先验证 RAG 效果。
- 暂时不需要实体关系和图谱视图。

快速入库速度最快，但后续不会自动得到对应知识图谱。如果之后需要图谱，需要在知识库文件中再触发图谱生成。

### 标准入库

标准入库会保留常规 RAG 入库流程，并可以生成受限规模的图谱数据。它适合大多数正式知识库场景：

- 既要向量检索，也希望有一定图谱关系。
- 希望控制图谱节点和关系数量，避免小文档生成过多图谱数据。
- 希望在效果和耗时之间取得平衡。

标准入库支持设置最多节点和最多关系。限制越小，入库越快，图谱越精简；限制越大，图谱更丰富，但耗时也会增加。

### 图谱入库

图谱入库更偏向完整构建知识图谱，适合你明确需要实体关系、图谱浏览和图谱增强分析的场景。它通常比快速入库更慢，也更依赖文档质量和模型抽取效果。

如果是首次导入大量网页或文档，建议先用标准入库并设置较小的节点/关系限制，确认效果后再逐步放大。

## 节点和关系数量限制

在标准入库和图谱入库中，可以设置最多节点和最多关系。这个限制只约束本次入库新增的图谱规模，不会删除已有图谱。

建议：

- 小文档或网页：20-50 个节点，20-80 条关系。
- 中等资料：50-150 个节点，80-300 条关系。
- 大型资料：分批入库，并逐步调高限制。

如果入库明显变慢，优先降低节点和关系限制，或改用快速入库先完成检索能力建设。

## OCR 方案选择

系统提供多种 OCR 方案，适用于不同场景：

### 方案对比

| 方案 | 适用场景 | 硬件要求 | 特点 |
|------|----------|----------|------|
| RapidOCR | 基础文字识别 | CPU | 免费开源，速度快 |
| PP-Structure-V3 | 表格、票据 | GPU | 专业版面解析 |
| DeepSeek OCR | 智能理解 | 无 | 云端服务，Markdown 输出 |

### 选择建议

- **个人使用或 CPU 环境**：选择 RapidOCR，免费且资源占用低
- **表格密集型文档**：选择 PP-Structure-V3
- **简单云服务**：选择 DeepSeek OCR

## 快速配置

### RapidOCR（推荐入门）

```bash
# 下载模型
hf download SWHL/RapidOCR --local-dir ./models/SWHL/RapidOCR

# 配置环境变量
MODEL_DIR=./models

# 启动服务
docker compose up -d api
```

### PP-Structure-V3（结构化）

```bash
# 启动服务（需要 GPU）
docker compose up paddlex -d
```

### DeepSeek OCR（简单云服务）

```env
# .env 配置（使用已有的 SiliconFlow 密钥）
SILICONFLOW_API_KEY=your-api-key-here
```

## 图片显示配置

上传文档中的图片需要正确配置才能在外部显示：

在 `.env` 中设置服务器 IP：

```env
HOST_IP=your_server_ip
```

## 注意事项

1. **图片文件必须启用 OCR**：否则无法提取内容
2. **GPU 要求**：PP-Structure-V3 需要 GPU 支持
3. **API 密钥**：部分服务需要额外的 API 密钥配置
4. **超时处理**：复杂文档解析可能耗时较长
5. **网页清洗需要人工确认**：自动清洗可能保留少量无关文本，建议入库前检查清洗结果
6. **图谱入库更慢**：节点和关系越多，入库耗时越长
